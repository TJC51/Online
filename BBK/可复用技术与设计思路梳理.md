## 1. 并发与异步处理

### 1.1 Redis 分布式锁（Redisson RLock）⭐

#### 1.1.1 基本模式：tryLock + finally 释放

**基本使用**

[`erp-pur/erp-purchase-app/src/main/java/io/terminus/erp/purchase/app/listener/PurPoSubmitListener.java`](../erp-pur/erp-purchase-app/src/main/java/io/terminus/erp/purchase/app/listener/PurPoSubmitListener.java)

```java
@MQSubscribe(topic = PUR_PO_TOPIC, tag = PUR_PO_SUBMIT)
@TrantorTransactional(rollbackFor = Exception.class)
public void purPoSubmit(PurPoSubmitEvent request) {
    // 1. 获取锁，key 包含业务ID
    RLock lock = redisson.getLock("purchase-po-submit-consume-" + request.getId());
    boolean hasLock = false;

    try {
        // 2. tryLock 获取，失败说明正在处理中 → 跳过
        hasLock = lock.tryLock();
        if (!hasLock) {
            log.warn("消息正在处理中，跳过: {}", request.getId());
            return;
        }
        // 3. 记录消费日志（消息去重表）
        purMessageConsumptionRecordsRepo.insertOrUpdate(record);
        // 4. 执行业务逻辑
        doSubmitBusiness(request);
    } finally {
        // 5. finally 中安全释放
        if (hasLock && lock.isLocked() && lock.isHeldByCurrentThread()) {
            lock.unlock();
        }
    }
}
```

**事务提交后释放锁**：通过事件发布将锁释放推迟到事务提交后，保证在锁持有期间数据库变更已落盘，此模式要求模块有 Spring Event 基础设施支持

[`tsrm-sourcing/tsrm-sourcing-app/src/main/java/io/terminus/tsrm/sourcing/sp/handler/lock/RedisLockReleaseEventHandler.java`](../tsrm-sourcing/tsrm-sourcing-app/src/main/java/io/terminus/tsrm/sourcing/sp/handler/lock/RedisLockReleaseEventHandler.java)

```java

@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
@Order(Integer.MAX_VALUE)
public void handle(RedisLockReleaseEvent event) {

}
```

#### 1.1.2 多锁模式（Redisson MultiLock）

**适用场景**：批量结算多个结算项时，需要对每个结算项加锁，Redisson MultiLock 将多个独立锁组合为一个原子锁

**复杂API**：使用 Redisson 提供的批量获取锁 API

[`erp-sett/erp-sett-app/src/main/java/io/terminus/erp/sett/app/processor/SettMultiLockProcessor.java`](../erp-sett/erp-sett-app/src/main/java/io/terminus/erp/sett/app/processor/SettMultiLockProcessor.java)

```java
@Component
public class SettMultiLockProcessor {
    @Autowired
    private RedissonClient redissonClient;

    public RLock getMultiLock(String lockPrefix, List<Long> ids) {
        List<RLock> locks = ids.stream()
            .map(id -> redissonClient.getLock(lockPrefix + ":" + id))
            .collect(Collectors.toList());
        return redissonClient.getMultiLock(locks.toArray(new RLock[0]));
    }
}
```

**简单API**：使用 Redisson 提供的单个获取锁 API + 循环 + 固定排序

[`erp-dn/erp-dn-app/src/main/java/io/terminus/erp/dn/app/service/bc/batch/DnRelateBatchService.java`](../erp-dn/erp-dn-app/src/main/java/io/terminus/erp/dn/app/service/bc/batch/DnRelateBatchService.java)

```java
// 获取锁时按 batchId 排序 → 所有线程以相同顺序获取 → 避免死锁
private List<RLock> getLocks(List<Long> batchIds) {
    return batchIds.stream()
        .sorted()                               // ← 关键：排序
        .map(id -> redisson.getLock("batch-remain-qty-lock-" + id))
        .collect(Collectors.toList());
}

// 释放时按逆序
private void releaseLocks(List<RLock> locks) {
    for (int i = locks.size() - 1; i >= 0; i--) {
        if (locks.get(i).isHeldByCurrentThread()) {
            locks.get(i).unlock();
        }
    }
}
```

#### 1.1.3 数据库行级悲观锁

**适用场景**：Redis 不可用时或需要与 DB 事务强一致的互斥操作。`REQUIRES_NEW` 确保锁操作独立提交，不随外层事务回滚。

**补充**：核心就是通过一个字段作为锁，更新前查询锁字段是否为空，只有为空时才能更新；更新时设值锁字段

[`erp-sett/erp-sett-app/src/main/java/io/terminus/erp/sett/app/engine/processor/data/lock/SettAggregationLockProcessor.java`](../erp-sett/erp-sett-app/src/main/java/io/terminus/erp/sett/app/engine/processor/data/lock/SettAggregationLockProcessor.java)

```java
// 独立事务 + UPDATE WHERE lockKey IS NULL 实现 DB 行锁
@Transactional(propagation = Propagation.REQUIRES_NEW, rollbackFor = Exception.class)
public int lockSettItemByIds(List<Long> ids, String lockKey) {
    SettItemTrPO settItem = new SettItemTrPO();
    settItem.setLockKey(lockKey);
    LambdaUpdateWrapper<SettItemTrPO> wrapper = Wrappers.lambdaUpdate();
    wrapper.isNull(SettItemTrPO::getLockKey)       // ← 仅锁定未被锁的行
           .in(SettItemTrPO::getId, ids)
           .eq(SettItemTrPO::getSettItemStatus, RECONCILED);
    return settItemTrRepo.update(settItem, wrapper);
}

// 释放锁：将 lockKey 设回 null
public void unlockByKey(String lockKey) {
    settItemTrRepo.update(null, new LambdaUpdateWrapper<SettItemTrPO>()
        .eq(SettItemTrPO::getLockKey, lockKey)
        .set(SettItemTrPO::getLockKey, null));
}
```

```java
public void asynchronousSyncErpOrder(Long orderId) {
    TrantorContext.Context ctx1 = TrantorContext.getContext();
    RequestContext.Context ctx2 = RequestContext.getContext();

    CompletableFuture.runAsync(() -> {
        try {
            TrantorContext.init();
            TrantorContext.setContext(ctx1);
```

```java
private void startConsumerLoop() {
    while (isRunning.get()) {       // AtomicBoolean 控制优雅关闭
        try {
            String message = queue.poll();  // RQueue 非阻塞轮询
            if (message != null) process(message);

            log.error("consume error", e);
        }
    }
```

[`erp-sett/erp-sett-domain/src/main/java/io/terminus/erp/sett/domain/util/EntityDiffUtils.java`](../erp-sett/erp-sett-domain/src/main/java/io/terminus/erp/sett/domain/util/EntityDiffUtils.java)

```java
// 比较新旧列表，自动计算新增/更新/删除，批量持久化
public static <T extends BaseModel> void diffEntities(
        BaseRepository<T> repository, List<T> originList, List<T> targetList) {
    // 计算差异
    Set<Long> originIds = originList.stream().map(BaseModel::getId).collect(Collectors.toSet());
    Set<Long> targetIds = targetList.stream().map(BaseModel::getId).collect(Collectors.toSet());

    // 新增
    List<T> newEntities = targetList.stream()
        .filter(e -> !originIds.contains(e.getId())).collect(Collectors.toList());
    // 删除
    List<Long> deletedIds = originList.stream()
        .map(BaseModel::getId).filter(id -> !targetIds.contains(id)).collect(Collectors.toList());
    // 更新
    List<T> modified = targetList.stream()
        .filter(e -> originIds.contains(e.getId())).collect(Collectors.toList());

    repository.insertBatch(newEntities);
    repository.updateBatch(modified);
    repository.deleteBatchIds(deletedIds);
}
```

```java
// ApplicationListener + ApplicationContextAware
// 应用启动后自动扫描所有 BaseRepository Bean，构建 entity → repository 映射
public class FinRepositoryScanner implements ApplicationListener<ContextRefreshedEvent> {
    private static Map<Class<?>, BaseRepository> tableRepositoryMap;

    @Override
    public void onApplicationEvent(ContextRefreshedEvent event) {
        Map<String, BaseRepository> repos = context.getBeansOfType(BaseRepository.class);
        for (BaseRepository repo : repos.values()) {
            Class<?> entityClass = GenericTypeResolver.getGenericParameter(
                BaseRepository.class, AopProxyUtils.ultimateTargetClass(repo));
            tableRepositoryMap.put(entityClass, repo);
        }
    }
}
```

### 8.1 并发处理方案选型

| 场景 | 推荐方案 | 核心文件（优先模块） |
|------|---------|-------------------|
| MQ 消费防重 | `RLock.tryLock()` + finally unlock | `PurPoSubmitListener.java` (pur) |

| 多资源锁定 | `RedissonMultiLock` + 排序 | `SettMultiLockProcessor.java` (sett), `DnRelateBatchService.java` (dn) |
| 需要事务一致性 | DB 行锁 `UPDATE WHERE lockKey IS NULL` | `SettAggregationLockProcessor.java` (sett) |
| 异步非阻塞 | `CompletableFuture.runAsync()` + 手动上下文传递 | `BcDelDnService.java` (dn), `OrderSignServiceImpl.java` (pur) |
| 异步入账 | `CompletableFuture.runAsync()` | `BcInvoiceOrderAppService.java` (sett) |
| 批量并发 | `ExecutorService` + `Future` + 优雅关闭 | `BcInvoiceOrderAppService.java` (sett) |
| 定时任务多线程 | `ThreadPoolExecutor` + `CallerRunsPolicy` | `DnAutoSubmitJob.java` (dn) |
